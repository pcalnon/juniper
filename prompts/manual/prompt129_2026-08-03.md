# Code signing via yubikey

## Background

a yubikey 5 is attached to this sytem via usb c.
a master "certification" gpg key with subkeys for signing, encryption, and authentication has been created in the /home/pcalnon/.gnupg/ directory
the /home/pcalnon/.gnupg/notes.txt file contains the keyid, key fingerprint, passphrase, and all other relevant information.
the yubikey user pin and admin pin are set at their factory defaults:

- user: 123456
- admin: 12345678

all of the keys, all credentials, and all of the data included in the notes files (including previously used values) should be considered throw-away.
these values are only being used to develop a working procedure for transferring local keys to the yubikey.
none of the existing data will be used for the actual, live version of the yubikey.

when the following command is used to transfer sub-keys to the yubikey

```bash
gpg --edit-key <KEY-ID>
```

and any of the sub-keys are selected, calling the `keytocard` command fails with the following error message:

gpg: KEYTOCARD failed: Invalid value

calling the `generate` command after launching the `gpg --card-edit` command successfully loads keys into the card.
however, the `generate` command appears to only allow key creation with defaults.
the defaults used include rsa2048 key type, and a master key that handles both certification and signing.
the requirements call for a distinct subkey for each of authorization, encryption, and signing, and a certification key whose only role is related to the subkeys

## Deliverable

use all local and remote resources needed--that can be used securely--to develop a working procedure to create a local ed448 key with subkeys that are:

- signing: ed448
- authentication: ed448
- encryption: x448

the procedure should allow key and subkeys to be created locally and then moved onto the yubikey.
the procedure should use distinct sub-keys for signing, encryption, and authentication.
the key and subkey types should be ed448, with encryption subkey being type x448.
